### 세계 구현 단위

기존 입구·보스 공터·4개 명소의 ID와 좌표를 보전하고 외곽 순환로로 256×224m를 확장한다. 지역마다 이름과 중심이 고정된 5소지역, 외곽 동굴·폐허·전망대 샛길과 3보물함을 둔다. Layout의 물 사각형과 교량·여울 데이터를 지도, 보행 제약, 실제 깊은물 정적 충돌과 렌더가 함께 쓴다. Height의 1m 삼각형 격자는 시각 메시·물리·발/전리품 투영을 공유한다. 구현 순서는 데이터/API와 높이, 시각·충돌, 경로·6지역 회귀와 그래픽 캡처다. 완료 기준은 모든 주/샛길의 캡슐 통행·명소/보물 접근, 물 감속/긴 변위 차단, 높이/법선 일치, 이전 드롭 안전 복원과 실제 그래픽 증거다.

세계 검증 결과: `world_test.gd` 54,475검사·0실패(`artifacts/world_030/frozen_world.log`), `world_traversal_test.gd` 실제 Player/WASD 48검사·0실패(`accepted_paths.log`). 6지역의 모든 주/샛길과 모든 출현점→길 접근선을 실제 캡슐로 검사했다. 1m 삼각형 지면·경사·다리 상판·렌더 수면 정점, 각 5소지역/3보물함, 깊은물 물리벽·22m 변위 차단, 교량/여울 통행, 늪0.6/얕은물0.7, 물속 구형 전리품 복원을 확인했다. 교량·여울·능선·보물함은 6지역 모두 실제 입력으로 걸었다. Windows 실행은 `Start-Process -Wait -PassThru -WindowStyle Hidden`으로 Godot 4.7.2에 `--headless --fixed-fps 60 --path game --script tests/world_test.gd`(또는 `tests/world_traversal_test.gd`)와 해당 절대 로그 경로를 전한다.

실제 Radeon 780M / Forward+ /1280×720에서 `world_capture.gd`로 준비된 위치의 교량6·동굴2·늪1 PNG를 촬영하고 모두 시각검수했다(`graphics_accepted.log`, `region_*_bridge.png`, `region_{0,3}_grotto.png`, `region_3_swamp.png`). 초기 숲 촬영이 수면 정점에 원점 지형 높이를 중복 적용하는 오류를 드러내 수정했고, 실수면 정점 검사로 보호했다. 초기 증거는 `initial_failure/region_0_bridge_offset.png`에 보전했다. 출현 후보의 연결 검사에서 드러난 기존 작은 다리 측면 접근은 기존3m 출현 여백을 접근선 전체에도 적용해 제거했다. 새 캐시 ID는 `r:cache_grotto`, `r:cache_ruin`, `r:cache_lookout`, 소지역은 `r:district_i`(i0..4)다. 통합 플레이·40적 성능·패키지/배포 판정은 별도 통합 단위에서 수행한다.

## 책임과 인터페이스

성능 보정 단위: 최종 40일반+1보스/Radeon780M/Forward+/1920×1080,30+120초에서 중앙30.797ms·p95 76.927ms로 목표미달했다(`dist/030-performance.log`). 먼저 같은 장면의3+12초 native 비용분해와 headless 차이로 CPU/GPU 원인을 구분하고, 파동당 최대2개의 근거 있는 수정 뒤 같은 조건으로 재측정한다. 배우/해상도/물리와 시각 형상·물 경계·판정·시계를 유지하며 중립/악화 변경은 되돌린다. 최종120초 판정은 통합 담당이 수행한다.

단독 native3+12초는526프레임·41명, 프레임18.488/43.754ms(중앙/p95), GPU9.379/10.813ms, 렌더CPU1.265/1.734ms, 물리21.337/30.347ms였다(`artifacts/world_030/perf_native_isolated.log`). 앞선CPU probe중첩 실행은 별도 참고로 보존하고 기준에서 제외했다. 첫 보정 파동은 원래9표본의 결과를 보전하는 body 검사 조기증명과, 높이/법선을 요구하지 않는 이동·통행 질의의 분리다. 전체 `surface_at`의 필드와 기본 동작은 보전한다.

첫 파동은54,475월드·31,392경계동치·78종/100행동·1402생태 검사에서0실패다. arena body5000회는134,153→4,865µs, 단독41명headless CPU p95는12.821→6.005ms, native3+12초는13.071/20.368ms로 개선했지만 목표미달이다. 다음 원인 후보인 화산 flora compound는 실제18몸체/17shape/최대1shape로 관련성이 없어 기각했다. 고정41좌표·180표본에서 원통 정지/0.1m 이동 평균3.461/5.955ms보다 전체 캡슐7.047/12.896ms가 느려 캡슐도 채택하지 않았다.

다음 가역 후보는 원통과 형상·반경·높이·마스크를 유지한 물리 엔진 비교다. 실제 설정은 `DEFAULT`이며 [4.7 ProjectSettings](https://docs.godotengine.org/en/4.7/classes/class_projectsettings.html)는 이를 GodotPhysics3D와 동일하게 정의한다. 현재 project.godot을 `artifacts/world_030/project_before_jolt.godot`에 그대로 백업하고 `physics/3d/physics_engine="Jolt Physics"`만 명시해 새 프로세스에서 측정한다. 중립/악화 또는 해소하지 못한 회귀가 있으면 백업으로 되돌린다. 채택 시 모든 지형·충돌·원거리/방어/분열·자연 입력·Linux 패키지를 새 엔진에서 재검증한다. [공식 Jolt 차이와 설정](https://docs.godotengine.org/en/4.7/tutorials/physics/using_jolt_physics.html)을 검토했으며 joint/RigidBody/face_index 계약은 본 게임에서 사용하지 않는다.

Jolt는실제격자정점ray누락으로월드187검사가실패했다. ±1mm에서만맞는실제PhysicsRayQuery를보전했고, HeightMap도같은누락이있어질의jitter나검사완화로감추지않았다. config는백업과동일SHA로복원했다. 다음진단은기존Godot/원통/Concave를유지하며 네꼭짓점이정확히0인cell만동일평면의큰사각형으로합치는것이다. 비평면1m삼각형·높이·법선·렌더·판정은유지하고면높이/ray/전경로회귀와실측개선이함께통과해야채택한다.

후보 비교의 마감 기록: 평면 병합은 물리120,520→32,282삼각형,1575개ray0누락·높이오차1.43µm였고 headless frame p95는14.471→13.272ms였다. 물리 중앙값은9.912→10.678ms라 채택하지 않았으며 진단 후보는 본편에서 사용하지 않는 `tests/terrain_collision_candidate.gd`에 보전한다. DEFAULT/원통/원래Concave 제품 구성을 유지한다.

분리 렌더 스레드 진단은 엔진이 매 프레임의 렌더 시간 조회가 동기화를 강제한다고 경고했다. 따라서 같은 정식 방식인 프레임 간격만 측정하는3+12초 대조를 추가했다. 기본 스레드는780프레임·중앙15.426ms·p95 24.848ms, 분리 스레드는1177프레임·중앙13.783ms·p95 19.847ms였다. 분리 조건에서 `_texture_2d_update`의 빈 이미지 오류도 발생해 기각했다. config의 기본 스레드는 변경하지 않았다. 모든 실행은41개체와1920×1080을 유지했다. 상세 로그는 `artifacts/world_030/perf_*`와 `tasks/evidence/ecology-contact-fixed.log`에 보전한다. config 원상복원 SHA-256은 `53122fe6c4053ab1f6a79c6dd64e5c03d3cfed8bc7295cdea5753ddbf74e9b91`이다.

이 단위에서 채택한 제품 변경은 첫 파동의 정확한 통행 질의 최적화뿐이다. 에디터 기반의 단기 native 목표는 아직 미달이다. 렌더 카운터를 사용하는 진단과 프레임 간격만 사용하는 정식 측정을 구분하며, 통합 담당은 실제 배포용 릴리즈 템플릿/PCK로 같은40+1·1080p·30+120초 기준을 추가 검증한다. 형상/물리/공격 수를 줄이거나 미달을PASS로 바꾸지 않는다.

실제 release 실행 파일의 같은41체/1080p 3+12초는중앙15.309ms·p9522.414ms로미달했다. 다음 제한 후보는 SphereShape3D다. 먼저 원통과 동일한41좌표/변위/마스크에서 구형의 순수 접촉 비용을 비교한다. 반경을 원래높이/2로 잡는 안은 높이·중심·발을 보전하고 수평 반경이5%커지며, 원래반경 안은 수평 범위를 보전하되 전체높이가약4.8%낮아지고 발에 맞춰 중심을 내린다. 큰 개선이 확인된 후보만 물가·경사·실제 조준/원거리·방어·분열·보스 회귀와 release native 기준으로 검증해 채택한다. 공격/진행 반경과 물리 반경의 차이는 명시하고 소리 없이 품질 기준을 낮추지 않는다.

Sphere는단독과평면병합조합모두고정접촉에서원통보다느려제품에반영하지않았다. 다음후보는비음수높이표본을검증한뒤 y=0 WorldBoundary를평지로쓰고, 양수꼭짓점을가진cell의기존1m Concave삼각형만남기는것이다. 울타리안의최상단지면·높이·렌더·원통·공격은같다. 지형아래 y<0의충돌집합은기존얇은면과달리채워지며, 울타리밖평면은기존경계/이동제약으로접근을막는다. 고정접촉→실제ray/캡슐/경사·수변→실제release성능이함께통과해야채택한다.

WorldBoundary 후보는 제품에 연결해 통합 검증 단계로 동결했다. 같은 프로세스의41원통/180표본/mask7에서 정지 평균3.070→0.886ms,0.1m 이동 평균5.722→2.274ms·p95 6.997→2.775ms였다(`tasks/evidence/ecology-contact-plane-pair.log`). 지형의 물리 삼각형은120,520→31,644개이며 모든 비평면cell의 원래 두 삼각형을 남겼다. 렌더 메시와 지형 높이 API는 바꾸지 않았다.

`game/scripts/world/collision_surface.gd`는 표본이 모두 비음수일 때 평면 y=0과 비평면cell Concave를 함께 만들고, 음수 표본이 있으면 원래 전체 trimesh로 돌아간다. `terrain.gd`의 기존 trimesh 생성 부분만 이 도우미 호출로 교체했다. 비음수 꼭짓점의 삼각형 내부 높이도 비음수이므로 울타리 안 최상단은 원래 h와 새 max(0,h)가 같다. 다만 기존의 얇은 지형 면과 달리 y<0은 충돌 반공간이며, y=0 면은 울타리 밖에도 존재한다. 정상 보행/드롭/출현은 기존 경계와 보정으로 울타리 안을 유지한다.

## 전투·장착 작업 단위

목표는 기존 60Hz 준비/판정/회복, 시전 시 피해 고정, 장비 변경으로 체력 회복 금지를 보전하면서 0.3 지형과 88도안의 실제 외형·효과를 전투 경로에 잇는 것이다. 순서는 실패하는 이동/프리뷰/효과 회귀 검증, 지형 제약과 프리뷰 격리, 효과 적용, 본 소켓 장착, 실제 렌더 확인이다. 세션·거래·보상은 이 작업에서 변경하지 않는다.

- `player.bind_terrain(world)`는 지형 공급자를 지정한다. 걷기·회피·돌진·넉백 모두 `surface_at`의 이동 배율과 `constrain_motion`의 깊은물/경계 제약을 통과한다. 공중 도약이나 벽 타기를 추가하지 않는다. 물/늪의 작은 접지 표시가 이동 상태를 설명한다.
- `effects.pierce`는 추가 투사체 대상 수 0~3, `lifesteal`은 실제 적용 피해의 0~0.12, `area`는 기술 반경 가산 배율 0~0.35다. 시전 시작 시 복사하고 이미 날아간 탄의 효과도 고정한다. 방어/무효/사망 후 추가 피해는 흡혈 재료가 되지 않는다. 회복은 최대 체력 안에서 누적 소수점을 보전한다.
- `preview_mode=true`를 트리 추가 전에 지정하면 플레이어 그룹·입력·충돌·필드 카메라·전투 피해를 만들지 않는다. `preview_cast(skill)`와 `preview_tick(delta)`는 실제 기술 데이터와 애니메이션을 별도 뷰포트에서 재사용한다. 렌더 프레임 수가 판정 프레임 수를 바꾸지 않는다.
- 장비는 `Loot.describe`의 도안·부위·visual을 보며 아이콘과 같은 GLB를 본 소켓에 붙인다. 기존 도안 0~28의 능력치/프레임은 유지한다. 새 도안의 역할은 같은 무기 계열 안에서 준비/거리 차이로 구별한다. 전투 중 교체는 진행 중 동작 외형을 유지한 뒤 반영한다.

검증은 `game/tests/combat_expansion_test.gd`에서 지형 배율·깊은물 회피/돌진/넉백, 관통 대상 수와 벽, 실제 피해 흡혈, 기술 반경, 프리뷰 격리를 검사하고 기존 player/arsenal 검증으로 프레임·피해/장비 변경 체력 계약을 재확인한다. 장비 렌더는 실제 프리뷰와 필드 카메라 양쪽에서 캡처한다.

### 생태 성능 재점검 · 2026-11-24 KST

최종 41개체 네이티브 통합 측정이 목표를 넘겨, 세계 담당은 surface/constrain 함수와 렌더 경로를, 생태 담당은 headless 고정 전투 틱에서 이동 제약/공격 예고 생성·갱신의 CPU 시간을 비교한다. 진단용 토글은 검수 스크립트 안에서만 사용하며 제품의 개체 수·해상도·공격 시점·패턴·외형을 줄이지 않는다. 측정으로 확인한 경로만 변경하고 기존 생태/지형 회귀와 같은 네이티브 최종 시나리오로 재검증한다.

첫 수정은 세계의 같은 물/경계 판정을 직접 읽는 `walkable_at/movement_surface_at`과 원래 9점 몸체 표본의 안전한 평지 빠른 경로다. 생태는 속도만 필요한 곳의 높이·법선 조회와 판정만 필요한 곳의 전체 표면 조회를 대체했다. `tests/ecology_cpu_probe.gd`의 단독 headless 41개체·360표본에서 적 갱신 평균은 7.380→4.312ms, 그 안의 이동 경계는 1.137→0.181ms, 예고 갱신은 0.398→0.214ms였다. 동일 진단의 합계 중앙값/p95는 6.904/12.821→4.386/6.005ms다. 엔진의 틱 밖 물리 처리와 GPU를 제외하는 진단값이므로 네이티브 16.7ms 합격 근거로 대체하지 않는다. 로그는 `ecology-cpu-probe-exclusive.log`와 `ecology-cpu-probe-fast-surface.log`다. 이 변경 뒤 적 검사(78종·100행동)와 생태 검사(현재 유효 스폰 후보에 따른 1,402검사)는 모두 0실패였고 여울의 실제 70% 이동 속도도 확인했다.

다음 진단 `tests/ecology_contact_probe.gd`는 각 측정마다 같은 41개체의 원점·속도를 복원하고 실제 `move_and_slide`만 잰다. 현재 물리 설정 값은 `DEFAULT`이며, 화산은 정적 몸체18개·실제 충돌 형상17개·한 몸체당 최대1개로 큰 식생 복합체가 없다. 마스크7·0.1m 입력의 180표본에서 원통41의 평균/p95는 5.955/7.080ms, 일반40만 같은 반경/전체높이의 캡슐로 바꾸면 13.377/16.857ms, 전체41캡슐은 12.896/16.218ms다. 정지 입력도 원통 3.461/4.083ms, 전체 캡슐 7.047/8.280ms로 악화됐다. 따라서 제품 충돌 형상은 원통을 보전한다. 실제 AI 궤적이 달라지는 효과와 별개로 동일 배치에서도 캡슐이 느림을 확인한 진단이며, 형상/충돌 마스크를 줄이는 변경은 채택하지 않았다. 원본은 `ecology-contact-fixed.log`다. 명시적 물리 엔진 선택 비교와 같은 네이티브 최종 성능 검증은 통합 담당이 이어간다.

Jolt 임시 설정에서 추가한 적 회귀는 일반/중간/필드보스 모두 높이0.52m 투사체가 원통 반경92%의 바깥쪽에도 실제 충돌함, 지역별 방어형6종의 앞/뒤 피해4/10, 진흙돌이 분열 반경0.47→0.61m와 원래 높이0.987m·중심0.4935m 보존을 확인했다. `ecology-enemy-jolt.log`의 78종·100행동과 `ecology-director-jolt.log`의 1,402검사는 0실패다. 이 결과는 Jolt의 전체 월드 호환성을 증명하지 않으며, 세계 담당이 발견한 경로 표본 ray/normal 실패와 네이티브 성능 합격이 별도 게이트로 남았다. 캡슐은 제품에 적용하지 않았다.
