# 성장과 탐험 구현 기록

2026-11-18 · 기획서 개정 기준. 0.2.0 기능 구현과 공개 배포 검증 기록이다.

### 0.2.0 공개 배포

사용자 요청에 따라 구현 변경을 main에 푸시하고 Windows·Linux의 회귀 검사, 패키징, 압축 해제 후 기동을 GitHub Actions에서 확인한다. 두 플랫폼이 통과한 커밋에 v0.2.0 태그를 발행하고 자동 게시 작업을 끝까지 확인한다. 게시된 패키지 두 개와 SHA-256 목록을 내려받아 파일 무결성과 실제 바이너리 기동을 다시 확인하는 것이 배포 완료 조건이다.

### 인수 검증

Radeon 780M에서 0.2.0의 확장된 화산을 Forward+·1920×1080으로 렌더했다. 불지옥 일반 몬스터 24체와 보스 1체를 유지하고 30초 예열 후 120초를 측정했다. 확장 초기 실행은 중앙값 17.087ms, p95 34.696ms였다. 실제 지형 표본을 재사용하고 평면 예고의 불필요한 세분화를 줄인 최종 실행은 **14,098프레임, 중앙값 9.342ms, p95 16.351ms**였다. 이 장면에서 p95 목표 16.7ms를 통과했다. [부하 장면 재현](../tests/field_performance.gd)

Windows Godot 4.7.2에서 세션 1,176개, 성장 66개, 장비 323개, 의뢰 134개, 확장 저장 115개 검사를 통과했다. 실제 0.1.0 원정 저장(9개 노선 클리어, 장착 공격력 45)을 읽은 뒤 이전 두 파일의 바이트가 보존됨을 확인했다. 레벨업 시 저장 실패를 주입해 재시도에서 경험치와 포인트가 한 번씩만 반영됨을 확인했다.

새 슬롯의 키보드·마우스 입력으로 숲에서 레벨 2, 힘 배분, 파편 사격 습득·R 배치·실제 발사, 첫 합성, 중간보스 두 번, 필드보스, 표석 귀환과 사막 입장을 확인했다. 한 회차에서 게임 시간 11.42초에 레벨 2, 12.28초에 첫 파편 사격, 136.77초에 사막에 도착했다. 자동 입력은 지도를 읽고 조준하므로 이 시간은 사람의 초회 플레이 시간과 다를 수 있다. 현재 확장의 전체 24노선 플레이 밸런스는 추가 검증 대상이다.

로컬 내보내기 프리셋으로 Windows ZIP과 Linux tar.gz를 생성하고 각각 Windows 및 WSL Ubuntu에서 압축 해제 후 실제 게임을 헤드리스로 120프레임 실행했다. 두 패키지 모두 별도 슬롯에 유효한 새 저장을 생성했다. Windows 소스 검증에는 새 성장·장비·기술·퀘스트·UI 입력 테스트를 포함했다. [빌드 스크립트](../scripts/build.py)

성장 화면·가방·상점·의뢰는 준비된 격리 슬롯으로 실제 버튼을 조작했다. 1280×720 창과 1920×1200 전체 화면에서 각각 71회 입력을 검증했다. 검수 중 발견한 가장자리 몬스터 재생성, 다른 장비를 선택한 채 합성한 결과의 능력치 비교, 구버전 K 키 충돌, 원거리 발사 후 이동에 따른 적 방패 판정 오류를 수정하고 원래 재현 조건으로 확인했다.

1. 성장·장비 데이터와 직렬화, 구버전 복구를 먼저 연결한다.
2. 플레이어의 전투 수치와 공격 동작, HUD·가방·기술 트리를 연결한다.
3. 여섯 필드의 탐험로·랜드마크·몬스터 분포를 실제 이동과 지도에서 검사한다.
4. 새 슬롯과 기존 슬롯으로 거래·전투 회귀와 양 플랫폼 빌드를 확인한다.

세션 UI는 기존 equipped(무기)와 함께 equipment(부위별 장착), stats(atk, crit, defense, max_hp, speed), progression(level, xp, xp_next, stat_points, skill_points, attributes, ranks, loadout)을 전달한다. 부위 키는 weapon/armor/shield/boots/helmet/ring/necklace, 무기 키는 sword/bow/staff/spear/mace, 능력치 키는 strength/vitality/agility다. loadout은 Q/E/R 순서의 기술 ID 배열이다. 거래 명령은 allocate_stat {stat}, learn_skill {skill}, equip_skill {slot:0~2,skill}, unequip {id}, buy {vendor,design}를 사용한다.

다음 레벨 필요 경험치는 30에서 시작해 레벨당 15씩 증가한다. 일반 처치 경험치는 `6+2×(필드레벨−1)`, 중간보스는 그 5배, 보스는 12배다. 힘 1당 공격력 2, 활력 1당 최대 체력 10, 민첩 1당 치명타율 1%p가 오른다. 기술 등급당 기본 계수의 20%를 더한다. 검·방패 교체와 스킬 배분은 각각 단일 저장 거래다.

새 저장은 `slot-v2-0.sav`와 `slot-v2-1.sav`를 교대 사용한다. 처음 0.1.0 데이터를 읽을 때 이전 두 파일을 보존하고 새 세대를 만든다. 이후에는 새 세대의 손상을 다른 정상 새 세대에서 복원한다. 탐험 의뢰는 테마마다 서로 다른 명소 두 곳을 발견하면 완료되며 같은 명소의 재방문은 한 번만 센다.

촌장 의뢰는 기존 합성·보스 의뢰의 번호와 지급액을 보존한다. 레벨 3, 기술 트리의 새 기술 습득과 3등급 강화, 원거리 무기와 방어구 착용, 여섯 지역별 서로 다른 명소 두 곳 발견에 코인을 지급한다. 레벨·등급은 성장 기록을 읽고, 장착·발견 실적은 해당 행동의 저장 거래에 포함한다. 같은 명소 재방문, 선행 의뢰 수령 전 달성, 구버전 수령 이력 복구, 재시작 후 중복 수령 차단을 검사한다.

Godot 4.7.2에서 `godot --headless --path game --script res://tests/quest_book_test.gd`로 의뢰 검사 134개를 통과했다. 독립 슬롯에서 숲 일반 몬스터 24마리와 중간보스 2마리의 처치 거래로 경험치를 획득하고, 촌장 보상과 장비 구입·장착·해제 이력을 재시작 후 확인했다. 보상 저장을 막은 경우 코인과 수령 여부가 함께 복구됐으며, 체크섬은 정상이지만 착용 기록이 손상된 경우 직전 저장본을 사용했다. 탐험 검사는 필드 데이터의 명소 ID와 세션 발견 거래를 사용했다.

필드는 128×112m 경계 안에 지역별 양쪽 큰길과 횡단로, 랜드마크 네 곳을 배치한다. 경로 데이터로 도로 마스크·사냥터·지도·발견 판정을 만들고 지면 메시와 충돌은 동일한 높이 표본을 쓴다. 일반 몬스터는 먼 구역을 떠나면 처치 보상 없이 가까운 사냥터에 재배치한다. 이전 바닥 아이템은 기존 좌표에서 새 지면을 따르며 장애물에 겹치면 인근 보행면으로 보정한다. 여섯 지역의 물리 경로, 랜드마크, 귀환과 지도 표식을 검사하고 숲의 두 길은 플레이어 입력 왕복으로 확인한다.

투사체의 정면 방어 판정은 실제 탄의 진행 방향과 명중 순간 몬스터가 바라보는 방향을 사용한다. 지팡이를 쏜 뒤 플레이어가 넉백으로 옆으로 밀려난 경우, 정면 사격·후면 사격·명중 직전 방패 회전을 실제 방패충과 비교한다. 갈퀴의 끌어당김과 기존 근접 방어 판정도 함께 검증한다.

공격력 10 지팡이와 숲 방패충으로 수정 전 정면 피해 6이 발사 후 측면 넉백에서 16이 되는 현상을 재현했다. 수정 후 두 정면 공격은 모두 6, 후면 공격과 비행 중 방패를 돌린 공격은 각각 16이었다. 투사체 명중으로 방패충 위치는 바뀌지 않았다. `arsenal_test.gd`, `player_test.gd`, `enemy_test.gd`, `retry_cleave.gd`를 다시 실행해 모두 통과했다.

### 필드 검증

2026-11-18, Windows Godot 4.7.2에서 여섯 필드의 물리 경계는 각각 128×112m였다. 입구에서 공터까지 서쪽·동쪽 도로의 중심선을 구간당 100점으로 나누고 실제 보행면의 3차원 거리를 합산했다. 숲 143.6/133.9m, 사막 162.7/143.6m, 묘지 141.2/148.4m, 늪 180.5/151.9m, 설산 174.2/155.7m, 화산 147.4/141.0m였다. [솔방울 숲 지도](../docs/media/field-map.png)

월드 검사 8,842건은 경계 충돌, 출현 위치, 네 갈래 경로, 랜드마크 접근, 기존 아이템 지면 보정과 장애물에서의 복구를 통과했다. 숲에서는 실제 플레이어 이동 입력으로 두 길의 왕복 지점 210개를 통과했다. 여섯 지역에서 각 28단계로 전투 없이 위치를 옮긴 검사에서는 초기 개체가 새 사냥터 개체로 교체되었고 경험치·코인·흔적이 유지됐다. 경계에서 12회 보충 검사를 반복해 출현 번호가 증가하지 않는 것도 확인했다. 일반 난이도 12개 조합의 역할·거리 검사, 45종 61개 공격 회귀 검사, M 키 지도·귀환·출현 예고 검사도 통과했다. Radeon 780M OpenGL에서 여섯 경관과 1280×720의 150% 지도 범례를 확인했다.

확장판 1080p 전투에서 보고된 프레임 지연의 원인을 살핀다. 기존 화산 25체 장면에서 바닥 예고를 지형에 투영하는 비용과 실제 지형·그림자 부하를 확인해 수정 범위를 정한다. 이동 경사, 다리의 보행면, 전투 배치와 그래픽 설정을 유지한다. 지형·몬스터 회귀와 같은 1080p 시나리오로 결과를 확인한다.

수정 전 진단은 Radeon 780M Forward+ 1920×1080, 일반 적 24체와 보스 1체로 3초 예열 후 12초 측정했다. GPU 중앙값/p95는 8.08/10.07ms, 물리 모니터는 19.22/37.59ms였다. 관찰한 공격 예고 175개가 모두 경사면용 메시를 만들었고 그중 63개의 투영 범위는 모든 언덕 밖에 있었다. 이 63개에서 12,912개의 정점이 만들어졌다. 렌더링·충돌 메시의 1m 높이 표본을 공유하고, 각 사각형 안에 높이가 있는 표본 수를 누적 합으로 검사하도록 변경했다. 보간에 참여할 수 있는 모든 격자점과 다리 데크·경사로를 포함해 평면 판정의 안전성을 검사한다. 수정 후 월드 8,863건, 몬스터 45종·61개 공격, 숲 플레이어 왕복, 무리 재배치, 지도 회귀가 통과했다. 숲 오르막 예고의 정점 최대 오차는 0.004m였다.
